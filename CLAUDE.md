# Verity — project instructions

## Propose big documentation/structure changes before making them

Before adding, removing, or restructuring a major section, concept, or framework in the
documentation (`README.md`, `README.es.md`, `docs/`) — not a small edit, fix, or correction —
describe the change and wait for confirmation before executing it.

This includes things like: introducing a new documentation concept (e.g. a "Labs" course
structure, a gamified "Break the Platform" section), adding a new narrative framing (e.g. "this is
an LLMOps lab"), or any change that adds or removes roughly a top-level section or more.

Small edits don't need this: fixing a broken link, translating existing content, correcting a
factual error, tightening wording, redesigning a diagram that already exists for clarity, adding a
missing cross-reference.

**Why:** earlier in this project, large structural additions (an educational "Labs" series, a
CI/lint-tooling narrative) were built without asking first, and then had to be removed entirely
once the user actually saw them. Proposing first avoids doing — and then undoing — real work.
